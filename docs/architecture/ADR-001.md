# Выбор архитектуры

**Статус:** принято для архитектурного паспорта.

**Контекст.** Игра разрабатывается одним разработчиком. Обычный режим работает на устройстве, а сайту и рейтингу нужен небольшой веб-сервис. Для рейтинга важно сохранить результат и обработать повтор после сбоя.

**Решение.** В основе паспорта — Unity-клиент и один веб-сервис ASP.NET Core с SQLite. Игра отвечает за контент, правила и прогресс. В проектном контракте сервис выдаёт токены установки, принимает результаты и отдаёт данные рейтинга и сборки.

| Вариант | Оценка |
|---|---|
| Только локальная игра | Проста, но не даёт общего рейтинга |
| Один веб-сервис с SQLite | Его проще развёртывать, а рейтинг можно обновлять одной транзакцией |
| Микросервисы | Требуют дополнительной инфраструктуры для небольшого рейтинга |

**Последствия.** Веб-сервис развёртывается одним приложением. Игра отправляет результат отдельно от игрового цикла, а сервер записывает рекорд и квитанцию в одной транзакции. Если при росте нагрузки запись начнёт задерживаться, стоит измерить эти задержки и рассмотреть переход на общую серверную СУБД.

**Риски.** После удаления игры для восстановления прогресса нужна резервная копия. Проверка диапазона времени отсекает невозможные значения. Защиту от подделки результата нужно будет прорабатывать отдельно.
